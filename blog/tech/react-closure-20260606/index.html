React - Closure

By sunwc 06 June 2026 Tech

一句話記住 — React 的閉包不是「一個還活著的人」，而是「一卷在特定 render 錄好的音」；問題通常不是 React 壞了，而是你在播放舊錄影。

React 的 Closure，比較像錄音機

如果 JavaScript Closure 是孩子帶著基因離開母體，

那 React Closure 更像是一台錄音機。

每次 render 時，React 都會錄下一份新的 callback。

之後真正執行時，播放的永遠是當時錄下來的那份內容。

錄音不會自己更新。

這就是 stale closure 發生的原因。

錄影帶模型：導演、拍攝、錄影、播放

導演（React Component）
  ↓
拍攝（每次 render）
  ↓
錄影帶（useEffect / callback）
  ↓
播放（稍後執行）
  ↓
舊錄影（stale closure）
技術概念錄影帶比喻
React Component導演
每次 render重新拍一次場景
useEffect callback一卷錄影帶
callback 裡讀到的 count錄影當下記下的內容
稍後執行 callback播放錄影
stale closure播放了舊錄影，以為是最新的

重點：錄影帶不是活生生的人。 它在錄製當下把內容刻進去，之後播放時不會自己更新。

先釐清三件事

  1. 每次 render，元件函式重新執行 — 導演重新開拍，場景裡的 count 可能是新的值。
  2. useEffect 的 callback 在那次 render 被建立 — 像錄影師按下 Record，把當下的 count 錄進去。
  3. callback 不會立刻執行 — 錄影先收好，React 等到適當時機（例如畫面更新後）才播放。
useEffect(() => {
  console.log(count);
}, []);

第一次 render 時 count = 0，錄影內容就是：

「我是 count = 0」

之後 count 變成 5，畫面更新了，但那卷錄影帶不會自己改內容——播放時仍是：

「我是 count = 0」

這不是 React 壞掉，是你在播放舊錄影。

正常情況：dependency array 幫你重新錄影

const [selectedItemIndex, setSelectedItemIndex] = useState(0);

useEffect(() => {
  console.log(selectedItemIndex);
}, [selectedItemIndex]);

[selectedItemIndex] 的意思是：

selectedItemIndex 變了
  ↓
重新錄影
  ↓
丟掉舊錄影帶
  ↓
播放新錄影帶

時間線：

  1. 第一次 render：selectedItemIndex = 0 → 錄影帶 A：「我是 0」
  2. React 播放 A → 印出 0
  3. 使用者勾選第三個 item → selectedItemIndex = 2 → 第二次 render
  4. 錄影帶 B：「我是 2」
  5. 依賴變了 → React 清掉 A、播放 B → 印出 2

重點：每次 render 都會產生新的 callback（新的錄影），dependency array 告訴 React「依賴變了就換新錄影來播」。

出問題的情況：stale closure（播放舊錄影）

「stale closure」聽起來很學術，白話就是：你以為播放的是現場直播，其實是舊錄影。

const [count, setCount] = useState(0);

useEffect(() => {
  const timer = setInterval(() => {
    console.log(count);      // 永遠印 0
    setCount(count + 1);     // 永遠設成 0 + 1 = 1
  }, 1000);
  return () => clearInterval(timer);
}, []); // 空陣列 = 只在第一次 render 錄一次、播同一卷

發生了什麼？

  1. 第一次 render：count = 0
  2. mount 後，useEffect 執行一次（[]），setInterval 註冊一個每 1 秒重複播放的錄影迴圈
  3. 錄影內容 capture 了這次的 count = 0：「我是 count = 0」
  4. 約 1 秒後（第 1 次播放）：印出 0，setCount(0 + 1) 把 state 設成 1，觸發 re-render
  5. 第二次 render：元件函式裡的 count 已是 1，但因為 []，useEffect 不會重錄，setInterval 仍播放同一卷舊錄影
  6. 之後每秒：錄影內容永遠是「count = 0」→ 永遠印 0，永遠 setCount(1) → 畫面上的 count 卡在 1
  7. 元件 unmount 時，cleanup 的 clearInterval(timer) 才會真正停止

重點：畫面上的 count 和 timer 錄影裡的 count，是兩份不同的記憶。re-render 更新了前者，但沒有更新後者。

第一次 render 錄影：「count = 0」
  ↓
每秒播放這卷舊錄影
  ↓
畫面上 count 可能已是 1，但錄影裡永遠是 0

這就是 stale closure：錄影還在播，但內容早就過期了。

怎麼修？

做法 1：dependency array — 變了就重錄

useEffect(() => {
  const timer = setInterval(() => {
    setCount(count + 1);
  }, 1000);
  return () => clearInterval(timer);
}, [count]); // count 變了 → 丟舊錄影、錄新的

count 變了
  ↓
重新錄影
  ↓
丟掉舊錄影帶
  ↓
播放新錄影帶

stale closure 解決了，count 會正常 0 → 1 → 2 → 3…

但代價是：每次 count 變了，整個 setInterval 會被拆掉重建——不是「同一卷錄影持續播」，而是「每次 count 變就重錄一卷新影帶」。

做法 2：functional update — 不要相信錄影帶

useEffect(() => {
  const timer = setInterval(() => {
    setCount(prev => prev + 1);
  }, 1000);
  return () => clearInterval(timer);
}, []);

不要相信錄影帶裡的 count
  ↓
改成直接問控制中心（React）目前是多少

prev => prev + 1 不是用閉包修閉包，而是避開閉包：

  • 不讀外層錄影裡的 count
  • React 把最新 state 當參數 prev 傳進來
  • 沒有外層變數可 capture，就不會 stale

同一個 timer 持續跑，每秒穩定 +1

若目標是「每 1 秒遞增的計數器」，這通常是更乾淨的做法。

做法核心timer 行為
[count]變了就重錄每次 count 變就重建
prev => prev + 1 + []不讀錄影，問 React同一個 timer 持續跑

錄影帶模型裡的三個角色

概念一句話跟閉包的關係
Inner function寫在外層函式裡的函式閉包通常發生在 inner function 上
Arrow function用 => 寫函式的語法只是寫法，本身不是閉包
Callback傳給別人、稍後才被呼叫的函式只是用途；可以是閉包，也可以不是

在 React 裡再加一個：

概念錄影帶比喻
useEffect callback在特定 render 錄好的音，之後播放
dependency array告訴 React 什麼時候該重錄
functional update播放時不讀錄影，直接向 React 要最新值

記住：閉包是一種行為，不是一種語法。 判斷標準只有一個——函式有沒有 capture 並使用外層變數。

收個尾

JavaScript 閉包用「媽媽與孩子」理解起源；React 閉包用「導演與錄影帶」理解播放。

導演（Component）
│
├─ 每次 render：重新拍攝
├─ useEffect callback：錄下當下的變數
├─ dependency array：變了就重錄
├─ stale closure：播放了舊錄影
└─ functional update：不讀錄影，直接問 React

在 React 裡，閉包不是記住「活的環境」，而是記住「某次 render 的快照」。 你得清楚自己播的是現場，還是舊錄影。
