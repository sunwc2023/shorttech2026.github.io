JavaScript - Closure

By sunwc 06 June 2026 Tech

一句話記住 — 閉包不是「外層變數還活著」這句話本身，而是函式帶著一份活的連結記得自己的起源；即使當初形成那份記憶的環境早已消失，連結仍然有效。

為什麼 closure 總讓人覺得抽象？

學 JavaScript 時，closure 的定義不難背——「函式記住它被建立時的外層環境」。但真正卡住人的，往往是下一個問題：

如果外層函式都結束了，裡面的變數為什麼還活著？

更麻煩的是，closure 幾乎一定會跟 var / let / const 和作用域一起出現。各自都懂，放在一起就糊了。

我後來不再只問「閉包怎麼運作」，而是換了一個更好記的角度：

如果閉包不存在，程式會變成什麼樣子？

這個問題，用一個生活化的比喻就能說清楚。

媽媽的環境 = 外層作用域

想像一個孩子在媽媽肚子裡成形。那段時間，孩子會接收到來自母體的影響——營養、荷爾蒙、情緒，都是外層環境的一部分。

在 JavaScript 裡，這就是 Lexical Scope（詞法作用域）：程式碼寫在哪裡，變數的可見範圍就跟著哪裡走。孩子（內層函式）在媽媽（外層函式）裡被定義，自然就處在那個環境之中。

function mother() {
  // 這裡是媽媽的環境
}

在談閉包之前，先認識這個環境裡的三種「收納規則」。它們決定變數放在哪裡、誰看得到；閉包決定的是離開之後還記不記得。

技術概念生活畫面
var整棟房子共用區，到處都找得到
let自己房間的抽屜，出房間就看不到
const戶口綁定不能換，生活內容可以改
Closure離開後，仍與起源保持活的連結

var = 整棟房子共用區

function mother() {
  if (true) {
    var toy = "Bear";
  }
  console.log(toy); // Bear
}

var 的邊界是整個 function，不是 if 或 for 這些 block。東西放在共用區，整棟房子都找得到。

let = 房間裡的私人抽屜

if (true) {
  let diary = "secret";
}
// console.log(diary); // ReferenceError

let 把東西收進 {} 這個 block。出了房門，就看不到了。

const = 戶口綁定，生活內容可以改

const baby = { name: "Lucy" };
baby.name = "Kevin"; // 可以——改的是內容
baby = {};           // 不行——換了一個人

const 保證的是綁定不能重新指向，不是內容永遠不能動。

作用域搞清楚之後，就可以問閉包真正關心的問題：孩子離開媽媽之後，還記不記得那段環境？

閉包 = 仍與起源保持活的連結

用 JavaScript 的話來說：

孩子在媽媽的環境裡成形（外層作用域）。只要那份連結還活著，行為就會部分受到繼承環境的影響。這就是閉包。

如果孩子完全切斷與繼承環境的連結，建立完全獨立的身份，那就不再是閉包在做的事了。

比喻程式碼
媽媽的環境外層函式 mother()
環境裡的 fear外層作用域的變數
孩子內層函式 baby()
活的連結閉包 capture 的外層變數
沒有連結內層函式沒有讀外層變數

接下來用三個例子，把這個比喻對照到程式碼上。

範例 1：閉包——仍與起源連結

function mother() {
  let fear = "spiders";

  return function baby() {
    console.log(fear);
  };
}

const child = mother();
child(); // spiders

孩子仍與媽媽的環境保持連結。

發生了什麼？

  1. mother() 執行時，在環境裡建立了 let fear
  2. baby 在定義當下，就把 fear 記住了
  3. mother() 結束，外層作用域理論上該消失了——但 child 還活著
  4. 每次呼叫 child()，讀到的都是同一份 fear

這就是閉包：函式帶著它被建立時的環境，一起往前走。

實務上：計數器是最典型的應用。需要「跨多次呼叫保留狀態」時，就靠這個 pattern：

function makeCounter() {
  let count = 0;
  return () => ++count;
}

const counter = makeCounter();
counter(); // 1
counter(); // 2

每次呼叫都更新同一份 count——同一份記憶，連結沒有斷掉。

範例 2：不是閉包——完全獨立生活

function mother() {
  let fear = "spiders";

  return function baby() {
    const ownBelief = "I am not afraid";
    console.log(ownBelief);
  };
}

const child = mother();
child(); // I am not afraid

現在孩子沒有使用任何外層變數。技術上，這個函式不再需要閉包，因為它沒有 capture 任何外部變數。

  • baby 仍是 inner function ✓
  • 但沒有「記住並使用」任何外層變數 ✗
  • 所以這不是閉包的有意義例子——沒有需要被保存的環境

「函式裡面再包函式」還差一步：內層得真的用到外層的變數，那份連結才有意義。

這也是很多人第一次學閉包時的誤解：看到巢狀函式就以為是閉包，其實關鍵在於有沒有 capture 外層變數。

範例 3：成熟的閉包——記得來處，仍做自己的決定

function mother() {
  let fear = "spiders";

  return function baby() {
    console.log(`I inherited ${fear}`);
    console.log("But I choose to overcome it.");
  };
}

const child = mother();
child();
// I inherited spiders
// But I choose to overcome it.

孩子記得自己的起源，卻不被過去完全定義。這仍是閉包——帶著與起源的活的連結，同時做出獨立決定。

狀態意思
Closure帶著與起源的活的連結
No closure與原始環境完全沒有連結
Mature closure記得繼承的環境，同時做出獨立決定

延伸：React 裡的閉包

useEffect、stale closure、dependency array 是另一個故事。媽媽與孩子的比喻解釋「什麼是閉包」很有效，但 React 更像每次 render 錄一卷影帶、之後播放——用「導演與錄影帶」來理解會更順。

容易混在一起的三個名字

閉包學到一半，常會跟這三個概念攪在一起：

概念一句話跟閉包的關係
Inner function寫在外層函式裡的函式閉包通常發生在 inner function 上
Arrow function用 => 寫函式的語法只是寫法，本身不是閉包
Callback傳給別人、稍後才被呼叫的函式只是用途；可以是閉包，也可以不是

記住：閉包是一種行為，不是一種語法。 箭頭函式可以形成閉包，一般函式也可以；callback 可以是閉包，也可以不是。判斷標準只有一個——內層函式有沒有 capture 並使用外層變數。

收個尾

一開始學閉包，我總以為重點是「外層變數怎麼還活著」。後來才發現，更值得想的是另一件事：

閉包讓函式有能力記得自己的歷史——但不代表它必須被那段歷史綁死。

媽媽的環境（外層作用域）
│
├─ 閉包：仍與起源保持活的連結
├─ 不是閉包：完全獨立，不讀外層變數
└─ 成熟的閉包：記得來處，仍做自己的決定

閉包，就是函式帶著它被建立時的歷史一起前行——即使當初建立那份歷史的環境，早已消失。
